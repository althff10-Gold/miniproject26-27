1. PROJECT OVERVIEW & PROBLEM STATEMENT
====================================================================================================

1.1 Background & Problem Statement:
Adolescent entrepreneurship is growing rapidly worldwide. However, existing startup incubator 
platforms (like AngelList, ProductHunt, or Y Combinator Startup School) are exclusively designed for 
legal adults. Teenagers (ages 13-19) face severe systemic hurdles:
  - Legal & COPPA Constraints: Minors cannot legally enter contracts or share personal information 
    without documented parental/guardian consent under COPPA (Children's Online Privacy Protection Act).
  - Online Safety Risks: Unmoderated messaging exposes minors to predatory behavior, inappropriate 
    content, cyberbullying, or illicit commercial solicitations.
  - Lack of Age-Appropriate Pedagogy: Standard incubator materials assume prior business, legal, and 
    finance degrees, lacking scaffolded gamification and step-by-step milestone mentoring.
  - Unverified Mentors: Open internet mentorship lacks identity vetting and background checks, posing 
    safety and liability hazards for schools and families.

1.2 Proposed Solution - TeenPreneur Hub:
TeenPreneur Hub is a specialized, secure digital startup incubation ecosystem engineered specifically 
for school and early-college founders. Key pillars include:
  1. Strict COPPA Compliance & Guardian Supervision: Automated parental consent workflows, age-gated 
     verification, and real-time guardian oversight dashboards.
  2. Verified Mentor Network: Strict background credential verification for industry professionals 
     before they can interact with students.
  3. AI-Powered Safety & Moderation: Dual-layer content moderation combining regex and NLP sentiment/PII 
     scanning on all communications and pitch submissions.
  4. Scaffolded Startup Incubation Pipeline: Guided 5-stage progression (Ideation -> Validation -> 
     Development -> Launch -> Growth) with milestone-based progress tracking.
  5. Integrated LMS: Bite-sized entrepreneurship courses, video lessons, and interactive quizzes.
  6. Virtual Pitch Competitions & Demo Days: Safe, structured showcase events with multi-criteria 
     rubrics evaluated by verified mentors.

2.2 Working Mechanism & End-to-End Request Lifecycles:

1. User Registration & COPPA Gate Lifecycle:
   a. User fills registration form in React UI (selects Student, Guardian, or Mentor).
   b. Student submits Date of Birth. Frontend sends payload to POST /api/v1/auth/register.
   c. Backend calculates age. If age < 13: registration rejected (COPPA statutory restriction).
   d. If age is 13-17 (Minor): User account is created with status = 'pending'. An approval 
      token (crypto 32-byte hex) is generated and linked to the Guardian's email address.
      Tokens are withheld; minor cannot login until guardian approves.
   e. Guardian receives notification/email with cryptographic approval link.
   f. Guardian navigates to approval modal, reviews student profile, and approves via 
      POST /api/v1/auth/guardian-approval.
   g. Link status updates to 'approved', student status updates to 'active', and both can login.
   h. If student is >= 18: Account becomes immediately 'active' without requiring guardian approval.

2. Startup Creation & Incubation Lifecycle:
   a. Student navigates to Student Dashboard -> "New Startup Venture".
   b. Student inputs startup name, industry (EdTech, FinTech, CleanTech, AI, Health), problem 
      statement, and proposed solution.
   c. Data is saved in `startups` and `business_ideas` tables (stage = 'ideation').
   d. Student clicks "AI Feasibility Evaluation": Backend proxies request to Python AI Microservice 
      (POST /evaluate-idea).
   e. AI analyzes problem clarity, market size, viability score (0-100), and outputs improvement tips.
   f. Student creates milestones (e.g. "Conduct 20 Customer Interviews", "Build Wireframes").
   g. Mentors review submitted proof (URLs, files) and mark milestones as completed.

3. Supervised Communication & Real-Time Moderation:
   a. Student initiates direct chat with assigned mentor via Socket.io WebSocket connection.
   b. Message text is intercepted BEFORE delivery: passed to AI Content Moderator (POST /moderate).
   c. The text is checked against:
      - Profanity & abusive language lexicons
      - PII leaks (phone numbers, personal addresses, social security/national IDs)
      - External unmonitored communication prompts (e.g. "text me on WhatsApp/Snapchat")
   d. If clean: Message is persisted to `messages` table and broadcasted to room.
   e. If flagged: Message is stored with `is_flagged = true`, severity calculated (low, medium, high, 
      critical), entry logged in `message_flags`, and alert dispatched to Admin Moderation Queue.
   f. Admin can inspect context and take action: dismiss, warn user, redact, or suspend account.

4. Learning Management System (LMS) Flow:
   a. Admin creates structured courses (e.g. "Startup Fundamentals", "Pitching to Investors").
   b. Each course has sequential lessons (markdown content, embedded videos, estimated duration).
   c. End of lesson features a quiz with multiple-choice questions (stored as JSONB in DB).
   d. Student submits answers -> server evaluates passing threshold (e.g. 60%).
   e. Upon passing, `learning_progress` increments; overall course completion badges awarded.

5. Virtual Pitch Event & Demo Day Flow:
   a. Admin creates a `pitch_event` with deadline and rubric guidelines.
   b. Student founder registers startup and submits pitch deck slides URL and video demo link.
   c. During Demo Day, verified mentors evaluate submissions using a 3-criteria rubric:
      - Innovation Score (1-10)
      - Feasibility Score (1-10)
      - Presentation & Pitch Delivery Score (1-10)
   d. System computes aggregate leaderboard and distributes feedback to founders.

It spans 7 interconnected domains:

   - `avatar_url`             : VARCHAR(500) (NULLABLE)
   - `last_login`             : TIMESTAMP (NULLABLE)
   - `failed_login_attempts`  : INT (DEFAULT 0)
   - `locked_until`           : TIMESTAMP (NULLABLE, Brute-force lockout timestamp)
   - `created_at`             : TIMESTAMP (DEFAULT CURRENT_TIMESTAMP)
   - `updated_at`             : TIMESTAMP (DEFAULT CURRENT_TIMESTAMP)

2. `students` (Adolescent founder profile extension)
   - `id`                     : INT (Primary Key, Auto-increment)
   - `user_id`                : INT (NOT NULL, UNIQUE, FK -> users.id ON DELETE CASCADE)
   - `school_name`            : VARCHAR(255) (NULLABLE)

5. AI MICROSERVICE ARCHITECTURE & WORKING
====================================================================================================

The AI Microservice operates as an independent, lightweight HTTP service on port 8000. It utilizes 
Python 3.12 standard library components to guarantee 100% dependency-free startup and maximum resilience.

Microservice Endpoints:
1. POST /moderate (Content Safety & PII Interception):
   - Scans text for:
     * Profanity, abuse, and harassment.
     * Personally Identifiable Information (PII) leaks: Phone numbers, street addresses, national IDs.
     * Inappropriate off-platform communication invites ("call me on", "whatsapp me at").
   - Response includes:
     * `is_safe`: Boolean (true / false)
     * `flagged_words`: Array of identified trigger terms
     * `severity`: 'low', 'medium', 'high', 'critical'
     * `category`: 'profanity', 'pii_leak', 'solicitation', or 'clean'

2. POST /evaluate-idea (Startup Feasibility & Market Analysis):
   - Input: `title`, `problem`, `solution`, `target_market`.
   - NLP heuristics analyze:
     * Problem clarity & pain-point severity.
     * Solution uniqueness and feasibility.
     * Target market specificity and addressable scale.
   - Outputs:
     * `overall_score` (0-100)
     * `dimension_scores` (Clarity, Feasibility, Market Potential, Innovation)
     * `strengths`: Formulated positive points
     * `recommendations`: Actionable improvements for next pitch iterations

3. POST /match-mentors (Algorithmic Mentorship Matcher):
   - Input: Startup `industry` and candidate mentor pool.
   - Computes weighted score based on domain keyword overlap and years of industry experience.
   - Outputs ranked list of mentors with rationale.

4. GET /health:
   - Returns microservice uptime, runtime environment, and active version status.

6. SECURITY, COPPA COMPLIANCE & PRIVACY ARCHITECTURE
====================================================================================================

6.1 COPPA Compliance Architecture:
  - Age Gate Enforcement: All student registrants must declare Date of Birth.
  - Direct Rejection for < 13: Absolute block preventing minors under 13 from registering without an 
    institutional school partnership.
  - Under-18 Authorization Gate: Minors aged 13-17 cannot activate their account or log in without 
    documented digital consent from a parent/guardian.
  - Cryptographic Tokens: 32-byte cryptographic hex tokens (`approval_token`) are used for one-time 
    parental verification over secure HTTPS channels.
  - Guardian Revocation: Guardians can revoke account access at any time, instantly suspending the student.

6.2 Platform Hardening & Defense-in-Depth:
  - Password Hashing: Industry-standard Bcrypt with 12 salt rounds; plain passwords never stored.
  - Stateless Authentication: Dual-token JWT (JSON Web Tokens) architecture:
    * Short-lived Access Token (15-minute validity) passed in Authorization header.
    * Long-lived Refresh Token (7-day validity) used to rotate access tokens securely.
  - HTTP Hardening:
    * Helmet: Sets Content-Security-Policy (CSP), X-Frame-Options, X-Content-Type-Options, etc.
    * CORS (Cross-Origin Resource Sharing): Dynamically validates localhost ports and production domains.
    * HPP (HTTP Parameter Pollution): Defends against parameter array injection attacks.
    * XSS-Clean: Sanitizes HTML tags and script elements in request payloads.
  - Brute Force & Rate Limiting:
    * Auth Limiter: Max 5 attempts per 15 minutes per IP on `/auth/login` and `/auth/register`.
    * Account Lockout: Automatically locks account for 30 minutes after 5 consecutive failed logins.
    * Global API Limiter: Max 100 requests per 15 minutes per IP address.
  - Audit Trail:
    * Immutable `audit_logs` record user ID, action, entity type, IP address, user agent, and timestamps.
